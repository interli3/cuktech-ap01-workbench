# 12 模式 A 硬件监控台：每个数字从哪来

模式 A · 硬件监控台（`tools/hardware_monitor/`）显示的是电脑**此刻的真实状态**：
CPU 功耗、温度、占用、风扇转速，GPU 功耗、温度、占用、显存，内存，
游戏帧率，以及充电器的四个口。

这篇文章讲清楚三件事：每个数字的来源、怎么自己验证一遍、出问题查哪里。

---

## 1. 字段对照表

| 屏上的位置 | 字段 | 真实来源 | 拿不到时 |
|---|---|---|---|
| CPU 卡 左上 | 温度 | LibreHardwareMonitor `CPU Package` / Temperature | 显示 `—` |
| CPU 卡 右上 | 占用 | Windows 计数器 `Processor Information / % Processor Utility` | 显示 `—` |
| CPU 卡 左下 | 功率 | LibreHardwareMonitor `CPU Package` / Power | 显示 `—` |
| CPU 卡 右下 | 风扇 | 主板 Super I/O（本项目机器是 Nuvoton NCT6687D）`CPU Fan` 的实际 RPM | 显示 `—` |
| CPU 卡 小字 | 型号 | `config.json` 的 `hardware.cpu_model`，纯装饰 | — |
| GPU 卡 左上 | 温度 | NVIDIA NVML `nvmlDeviceGetTemperature` | 显示 `—` |
| GPU 卡 右上 | 占用 | Windows `GPU Engine` 里 `engtype_3D` 各引擎求和后取最忙的那组 | 显示 `—` |
| GPU 卡 左下 | 功率 | NVML `nvmlDeviceGetPowerUsage` | 显示 `—` |
| GPU 卡 右下 | 风扇 | NVML `nvmlDeviceGetFanSpeedRPM` | 显示 `—` |
| 内存条 | 已用/总量 | `psutil.virtual_memory()` | 不会失败 |
| 显存条 | 已用/总量 | NVML `nvmlDeviceGetMemoryInfo` | 显示 `—` |
| 右上 FPS 卡 | 帧率 | PresentMon 的真实 Present 事件 | 显示 `—`，标题显示「等待游戏」 |
| 顶部银白卡 | 充电 | 小米云 RPC `siid=4`，`piid` 4/7/9/11 = C1/C2/C3/USB-A | 显示「等待充电数据」 |

> 「显示 `—`」是刻意的设计，不是 bug。宁可让屏上出现一条横线，
> 也不能把「读不到」写成「0 W / 0 °C」，那样会误导人以为机器在待机。

## 2. 装什么

### 2.1 Python 包

```bash
python -m pip install -r requirements.txt
```

这个模式需要 `psutil`（内存/进程）和 `nvidia-ml-py`（N 卡的功耗温度显存）。
A 卡或核显可以删掉 `nvidia-ml-py` 那一行，GPU 卡会整块显示 `—`。

### 2.2 MSI Afterburner（关键）

CPU 的功耗、温度、风扇转速不是 Windows 自带的接口能读的，
必须靠 **LibreHardwareMonitor** 这个库去读主板传感器。
装 MSI Afterburner 时它会顺带装 **RTSS**，RTSS 的插件目录里就有本项目要的两样东西：

```
C:\Program Files (x86)\RivaTuner Statistics Server\Plugins\Client\
├── LHMDataProvider\LibreHardwareMonitorLib.dll      ← CPU 功耗/温度/风扇
└── PresentMonDataProvider\PresentMon-2.3.1-x64.exe  ← 游戏帧率
```

这两条路径是程序默认会去找的。装在别处也没关系，在 `config.json` 里写死：

```json
"hardware": {
  "lhm_dll": "D:/Tools/RTSS/Plugins/Client/LHMDataProvider/LibreHardwareMonitorLib.dll",
  "presentmon": "D:/Tools/RTSS/Plugins/Client/PresentMonDataProvider/PresentMon-2.3.1-x64.exe"
}
```

不想装 Afterburner，也可以直接下 [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor)
的 release 包，把里面的 `LibreHardwareMonitorLib.dll` 拷到 `tools/hardware_monitor/` 下，
程序会自己找到；PresentMon 的官方 release 在
[GameTechDev/PresentMon](https://github.com/GameTechDev/PresentMon)。

> 权限：读 CPU 功耗要访问 MSR，**普通权限经常只能读到温度**。
> 如果 `watts` 一直是 `—` 而温度正常，用管理员身份开一个命令行再跑一次。

## 3. 三步验证（按顺序做，别跳）

### 第一步：单独验传感器

不联网、不开端口，只跑一次采样：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/hardware_monitor/cpu_sensor.ps1 -ParentPid 0 -Once
```

正常输出长这样（一行 JSON，数值每次不同）：

```json
{"at":1794161913.794,"cpu_fan_rpm":939,"watts":79.97023,"temperature":49,"usage":67.469,"gpu_3d":83}
```

- `watts`、`temperature`、`cpu_fan_rpm` 都是 `null` → 没找到 LHM 的 dll，回第 2.2 节
- 数字正常 → 传感器这一层通了，进第二步

### 第二步：在本机生成一张面板图

```bash
python tools/hardware_monitor/runtime.py --probe
```

它会跑 6 秒，然后在 `tools/hardware_monitor/` 下留两个文件：

- `probe.png`：直接打开就能看，效果和屏上一模一样
- `probe.gif`：真正发给设备的文件，大小必须 ≤ 24572 字节

同时终端会打印一行完整数据。看到真实数字就说明采集 + 绘图都通了。

> 前 2～3 秒 CPU 那几格是 `—`，因为 LibreHardwareMonitor 打开传感器库需要时间。
> 这是正常的，不是故障。

### 第三步：起正式服务

```bash
python tools/hardware_monitor/runtime.py
```

看到这两行就是起来了：

```
模式 A 服务已启动：http://192.168.1.160:18765/screen.gif
```

然后在**同一台电脑**的浏览器里打开 `http://电脑IP:18765/health`，
应该返回一段 JSON，其中 `ok` 是 `true`。

再打开 `http://电脑IP:18765/screen.gif`，能看到一张 320×240 的图。

浏览器能开、屏幕开不了 → 是 Windows 防火墙没放行 18765 端口，
或者屏幕 IP 和配置里的 `device.device_ip` 对不上。

## 4. 配置项

`config.json` 里跟这个模式有关的只有 `hardware` 这一段：

```json
"hardware": {
  "did": "",
  "port": 18765,
  "dash_port": 0,
  "presentmon": "",
  "lhm_dll": "",
  "cpu_model": "i5-14600KF",
  "gpu_model": "RTX 5070",
  "art_dir": "runtime/loader-install",
  "log_dir": "runtime/logs",
  "ignore_processes": []
}
```

| 字段 | 作用 | 不填会怎样 |
|---|---|---|
| `did` | 这块屏的 DID；留空就用 `device.did` | 用 `device.did` |
| `port` | 服务端口，也是加载器里写死的那个端口 | 默认 18765 |
| `dash_port` | 想额外开一个端口看 JSON 就填，比如 18767 | 0 = 不开 |
| `presentmon` | PresentMon 的 exe 路径 | 自动去 RTSS 目录找 |
| `lhm_dll` | LibreHardwareMonitorLib.dll 的路径 | 自动去 RTSS 目录找 |
| `cpu_model` / `gpu_model` | 屏上那行小字型号，纯装饰 | 显示 `CPU` / `GPU` |
| `art_dir` | `screen.gif` 落盘位置（老加载器会来取） | `runtime/loader-install` |
| `log_dir` | 日志目录 | `runtime/logs` |
| `ignore_processes` | 不想被算成「游戏」的进程名 | 只过滤内置的系统外壳进程 |

## 5. 画面是怎么排的

一块 320×240 的画布，分区固定：

```
y=40    标题「实时硬件监测」            进程名（右对齐）
y=55    充电卡（8~208）                FPS 卡（214~311）
y=108   CPU 卡（8~156）                GPU 卡（163~311）
y=181   内存条（8~156）                显存条（163~311）
y=220   时间                           「实时更新」+ 呼吸灯
```

三条实现细节，改代码时会踩到：

1. **GIF 必须 ≤ 24572 字节。** 传图协议每块 24576 字节，其中 4 字节是长度头。
   超了就直接抛异常，不会悄悄截断。现在这套配色 + 128 色 Median Cut
   稳定在 20～23KB。
2. **顶部 40 像素不要用。** 屏上那一条留给原厂固件自己画东西，
   自绘内容从 y=40 开始才不会打架。
3. **一共三帧。** 第一帧正常，第二帧呼吸灯亮点（4.5 秒），
   第三帧是「监测数据已过期」的兜底画面（60 秒）。
   电脑关机、断网的时候屏上就该写「已过期」，而不是把最后一帧冻在那儿骗人。

## 6. 出问题查这里

| 现象 | 原因 | 怎么办 |
|---|---|---|
| CPU 三格全是 `—` | 没找到 LHM 的 dll，或没有管理员权限 | 跑第 3 步的 `-Once` 自检，看 `watts` 是不是 null |
| 只有 CPU 温度、没有功耗 | 权限不够，读不到 MSR | 用管理员身份的终端启动 |
| FPS 一直 `—` | PresentMon 没找到，或当前没有游戏在出帧 | 看终端有没有「没找到 PresentMon」的提示 |
| FPS 显示的是浏览器/桌面 | 前台窗口被识别成「游戏」 | 把进程名加进 `ignore_processes` |
| 屏上一直是「监测数据已过期」 | 电脑端服务没跑，或超过 3 秒没新数据 | 看 `runtime/logs/realtime-monitor.log` |
| 屏上画面对着，但数字不动 | 服务在跑但采集线程挂了 | 看 `runtime/logs/metrics-sensors-error.log` |
| `python` 报 `No module named psutil` | 没装依赖 | `python -m pip install -r requirements.txt` |
| 浏览器能开、屏幕开不了 | 防火墙 / IP 不一致 | 放行 18765，核对 `device.device_ip` |
| 屏幕有画面但比例不对 | 加载器端口和 `hardware.port` 不一致 | 两边改成同一个端口 |

日志都在 `runtime/logs/`：

- `realtime-monitor.log`：每秒的采样和请求记录
- `metrics-sensors-error.log`：PowerShell 传感器子进程的报错
- `realtime-monitor-error.log`：主进程的异常堆栈

## 7. 已知边界

- **只有 Windows。** 依赖 NVML、Windows 性能计数器、PowerShell、PresentMon，
  换到 Linux/macOS 要重写整个采集层。
- **只有 N 卡有 GPU 数据。** A 卡要换 `rocm-smi` 或 ADL，本仓库没做。
- **CPU 风扇只在认得出的主板上有效。** Super I/O 芯片型号不在 LHM 支持列表里
  就是 `—`，笔记本尤其常见。
- **PresentMon 不是所有游戏都吃。** 反作弊、独占全屏、部分 Vulkan 游戏可能采不到。
- **没有做长时间稳定性测试。** 连续跑几天的内存占用、句柄泄漏没验证过。
- **采集间隔 1 秒。** 想更快会让传图链路撑不住（每秒一块 24KB 已经是协议上限）。
