# 03 0055：它不是降级目标，是一个未知状态

## 1. 先把方向说清楚

“从 0041 降级到 0055”这句话是反的。

- `0041 → 0031` 是**降级**，已经真机成功两次，方法在
  [02-降级-0041到0031.md](02-降级-0041到0031.md)。
- `0041 → 0055` 是**升级**。0055 是比 0041 更高的版本，不是更低。
- 我们**没有**刷过 0055，也没有任何 0055 真机成功/失败记录。
  所以它只能写成“未知状态”，不能写成教程。

如果你看到某个帖子里说“0041 降 0055”，先确认他是不是把版本号写反了。
按酷态科云端 OTA 链，0055 在 0041 后面。

## 2. 0055 是什么

| 项目 | 内容 |
|---|---|
| 版本号 | `1.0.2_0055` |
| 文件大小 | 6,389,800 字节 |
| 相对 0031 | 少 414,720 字节，布局明显不同 |
| 云端更新日志 | ① 支持插件设置切换功率界面主题 ② 支持屏幕显示 iPhone 18 系列及 iPhone Duo 型号 ③ 修复已知问题，优化用户体验 |
| 自定义能力 | 没有任何“开放第三方固件/允许降级”的说明 |
| 真机验证 | 我们没有刷过；没有成功记录，也没有变砖记录 |

文件大小变化很关键。0041 的降级钥匙依赖“写入器先取反首字节”的具体行为；
0055 重新编译、代码重排，这个行为是否保留、签名拒绝分支是否还提前退出，
都没有证据。拿 0041 的经验直接套 0055，是赌博。

## 3. 为什么不能提供“0055 降级教程”

1. **没有真机证据。** 本项目只写实际做过的操作；没做过的，不编步骤。
2. **签名闸门更严。** 现有 0031 加载器只认 `1.0.2_0031`，0055 上装不进去。
3. **降级钥匙可能失效。** 首字节预反转是为 0041 写入器设计的；
   0055 的写入器没有逆向验证。
4. **变砖代价高。** 设备彻底离线且无法配网时，软件救不了，只能走售后。
5. **上游也没有公开方案。** slepher 线的成果基于 0041 基线；
   没有 0055 的首次安装 SOP 或成品 ROM。

所以本仓库对 0055 的态度是：**存档、比对、提醒，不提供刷法。**

## 4. 如果你已经在 0055 上

先不要做任何写入操作。按顺序确认：

1. 米家里设备是否还在线、能否正常配网；
2. 屏幕是否能显示原厂界面、旋钮是否能切页；
3. 记录 `miIO.info` 返回的 `fw_ver`、`hw_ver`、`life`；
4. 如果只是想恢复原厂，0055 本身就是原厂，不需要“恢复”；
5. 如果想装第三方加载器，目前没有可用路线，等上游或售后。

不要尝试：

- 用 0031 的加载器直接刷 0055；
- 用首字节预反转的 0031 往 0055 上发；
- 在米家反复点升级/降级；
- 拆机短接（没有公开的 0055 救砖点位）。

## 5. 0055 原厂固件为什么放在仓库里

`firmware/原厂_0055.bin` 只用于：

- 确认版本差异和文件大小；
- 未来如果有人做出 0055 的研究，可以拿它做比对；
- 校验自己的设备到底在哪个版本。

它不是给刷机用的。仓库里没有任何脚本会把 0055 写进设备。
`tools/restore_factory.py` 只认 0031，`downgrade_0041_to_0031.py` 只认 0041。

## 6. 一句话总结

**0031 是能改的版本，0041 是能降回 0031 的版本，0055 是别碰的版本。**

如果你现在的设备是 0041，按第 02 章降级；
如果已经是 0055，保持原样，别拿它做实验。
