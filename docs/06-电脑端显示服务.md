# 06 电脑端显示服务

## 1. 它负责什么

`tools/display_service.py` 是整块屏的“大脑”：

- 每 60 秒读一次账户余额；
- 每 5 秒读一次充电功率，并重画 GIF；
- 对屏幕提供两个入口：
  - `/screen.gif`：单张 GIF，兼容每分钟取图的旧加载器；
  - `/live.bin`：300 块长连接，每秒一块，给新加载器用；
- 对调试提供 `/health`；
- 把当前数据写到 `run/current.json`，把预览写到 `run/preview.png`。

它不修改设备，只读云端/本机数据，然后生成图片。

## 2. 数据从哪来

| 板块 | 来源 | 失败时 |
|---|---|---|
| Codex 额度 | 本机 `codex.exe app-server` 的 `account/rateLimits/read` | 显示 `—`，不伪造 |
| WorkBuddy 积分 | 本机 `http://127.0.0.1:8791/snapshot`，取两个账号 | 显示 `—` |
| DeepSeek 余额 | 官方 `/user/balance`，密钥用 DPAPI 加密 | 显示 `—` |
| 充电功率 | 小米云 RPC，`siid=4`，`piid=4/7/9/11` | 显示“数据暂不可用” |

### Codex

服务会扫描 Codex 的版本目录（默认 `%LOCALAPPDATA%/OpenAI/Codex/bin`），
优先使用上次成功的版本。客户端升级会新建哈希目录，所以不能写死路径。

启动方式：

```text
codex.exe app-server --listen stdio://
```

然后按顺序发：

```json
{"id":1,"method":"initialize","params":{...}}
{"method":"initialized","params":{}}
{"id":2,"method":"account/rateLimits/read","params":null}
```

`usedPercent` 转成剩余值 `100-usedPercent`，再按窗口时长分成
“5 小时”和“本周”。重置时间用 `resetsAt` 换算成本地时间。

### WorkBuddy

本机桥接服务 `8791` 返回的 snapshot 里有两个账号的积分。
接口没有账号时显示破折号，不补 0。

### DeepSeek

密钥用 Windows DPAPI 加密保存在 `run/deepseek_key.bin`（路径可配）。
换 Windows 用户或重装系统后要重新 `python tools/credentials.py set <key>`。
磁盘上没有明文，日志和截图里也不会出现。

### 充电功率

单独模块 `tools/power_reader.py`，后台线程每 5 秒读一次，
只接受“四个端口都返回合法整数”的完整响应。读失败不覆盖旧值，
样本超过 15 秒显示不可用。细节见 [08-功率读取.md](08-功率读取.md)。

## 3. 刷新节奏

```python
data = refresh()                 # 余额 + 功率，生成第一张图
balance_due = now + 60
while True:
    sleep(5)
    if now >= balance_due:
        data = refresh()         # 重新读余额
        balance_due = now + 60
    else:
        refresh_power(data)      # 只复制功率缓存并重画 GIF
```

为什么分开：

- 余额接口有频率限制，60 秒足够；
- 功率要跟着插拔变化，5 秒一次；
- 每次重画 GIF 约 20KB，5 秒一次完全扛得住；
- 设备每秒取图，所以端到端通常是 1～6 秒。

## 4. 两个入口

### `/screen.gif`

```http
HTTP/1.1 200 OK
Content-Type: image/gif
Content-Length: 20xxx
Connection: close
Cache-Control: no-store
```

给每分钟取图的旧加载器、浏览器调试、预览脚本用。

### `/live.bin`

```http
HTTP/1.1 200 OK
Content-Type: application/octet-stream
Content-Length: 7372800
Connection: close
```

`7372800 = 300 × 24576`。每个块：

```
4 字节小端长度 + GIF 字节 + 补零到 24572 字节
```

每秒发一块，发满 300 块后关闭。只允许配置里的 `device.device_ip` 访问，
其它 IP 返回 403。

### `/health`

```json
{
  "ok": true,
  "uptime": 874,
  "requests": 553,
  "last_request": 1794160461.14,
  "median_request_interval": 1.000002,
  "device_diagnostic": {"v": 2, "g": 300, "a": 299, "e": 0}
}
```

`requests` 是最近 600 次请求的窗口，不是历史总数。
`median_request_interval` 接近 1 秒，说明设备在正常取图。

## 5. 配置项

| 字段 | 说明 |
|---|---|
| `device.did` | 目标屏幕 DID，纯数字 |
| `device.device_ip` | 屏幕 IP，用于 `/live.bin` 白名单和请求计数 |
| `network.bind` | 电脑监听地址，填局域网 IP，不要填 `0.0.0.0` |
| `network.display_port` | 默认 18766；硬件监测模式用 18765 |
| `paths.state_dir` | GIF、current.json、日志目录，默认 `run/` |
| `sources.workbuddy_snapshot` | 本机快照地址 |
| `sources.deepseek_endpoint` | DeepSeek 余额接口 |
| `sources.deepseek_key_store` | DPAPI 密文路径 |
| `sources.codex_bin_root` | Codex 版本目录 |

有多台设备同时跑时，每台要改三样：DID、端口、`state_dir`；其它可以共用。一块屏不用管这段。

## 6. 开机自启

用任务计划程序，不要用 Windows 服务：

- 触发器：当前用户登录时；
- 程序：`pythonw.exe`（无控制台窗口）；
- 参数：`tools/display_service.py`；
- 起始目录：仓库根目录；
- 失败重启：最多 3 次，间隔 1 分钟。

为什么不能用服务：DPAPI 密钥绑定当前 Windows 用户，
服务账号解不开，DeepSeek 余额会一直显示 `—`。
电脑重启后必须先登录桌面，服务才会起来。

## 7. 失败表现

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 屏幕一直“未充电” | 没插设备，或四个端口都 0A | 正常；插上手机看 1～6 秒内变化 |
| 屏幕“数据暂不可用” | 云端读取失败/样本超过 15 秒 | 看日志、查代理、查米家在线状态 |
| 只有 DeepSeek 是 `—` | DPAPI 解不开/密钥没配 | `python tools/credentials.py check` |
| Codex 一直 `—` | 客户端升级后路径变了/未登录 | 手动跑一次 `codex.exe app-server` 看报错 |
| `/live.bin` 403 | 屏幕 IP 和配置不一致 | 改 `device.device_ip`，不要重刷 |
| 画面不换 | 服务没起/端口被占/防火墙 | 看 `/health`，查 18766 |

## 8. 调试命令

```bash
# 只生成一张图，不起服务
python tools/display_service.py --once

# 看健康状态
curl http://电脑IP:18766/health

# 看当前数据（可能含余额，别公开）
type run\current.json
```

`run/current.json` 只用于本机调试，不要提交到仓库，
也不要把含真实余额的截图发到公开场合。
