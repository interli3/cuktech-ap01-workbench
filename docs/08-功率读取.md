# 08 充电功率读取

## 1. 数据在哪

AP01 的充电端口信息不在“云端配置属性”里，而在 MIoT service 4 的
打包整数里。只读这四个：

| siid | piid | 端口 |
|---:|---:|---|
| 4 | 4 | C1 |
| 4 | 7 | C2 |
| 4 | 9 | C3 |
| 4 | 11 | USB-A |

请求长这样：

```json
{
  "method": "get_properties",
  "params": [
    {"did": "你的DID", "siid": 4, "piid": 4},
    {"did": "你的DID", "siid": 4, "piid": 7},
    {"did": "你的DID", "siid": 4, "piid": 9},
    {"did": "你的DID", "siid": 4, "piid": 11}
  ]
}
```

不要一次查 150 个属性，会返回空。就查这四个。

## 2. 怎么解包

每个端口的值是一个 32 位整数：

```python
volts = ((value >> 24) & 255) / 10
amps  = ((value >> 16) & 255) / 10
watts = volts * amps
```

低 16 位是别的字段，不参与电压电流计算。

例子：`0xC30F1703`

```
最高字节 0xC3 = 195 -> 19.5 V
次高字节 0x0F = 15  -> 1.5 A
功率 = 19.5 × 1.5 = 29.25 W
```

这和原厂功率页显示一致，说明字段解释是对的。

## 3. 为什么显示 `≈`

电压和电流都只有 0.1 的分辨率，乘出来的功率是量化后的乘积，
不是设备内部的精确瓦数。所以屏幕上前缀 `≈`，表示约算值。

另外，协议标称 55W 是“协商档位”，不是当前实时输出。
手机在 9V/2A 时就是 18W，不会因为充电器标 55W 就显示 55W。

## 4. 采样和过期

`tools/power_reader.py`：

- 独立后台线程，每 5 秒读一次；
- 只有四个端口都返回合法整数，才更新缓存；
- `type(value) is int`，排除布尔值（`False` 会被当成 0）；
- 读失败不写 0，旧样本自然过期；
- 样本超过 15 秒，`sample()` 返回 `None`，界面显示“数据暂不可用”。

为什么不做“失败就显示 0”：
插着手机但云端读失败时，0W 会让人以为没在充电，比“不可用”更误导。

## 5. 显示规则

| 情况 | 屏幕 |
|---|---|
| 只有一个端口 `watts > 0` | 端口名、`≈功率`、电压、电流 |
| 多个端口 `watts > 0` | 只显示总功率 |
| 四个端口都 0 且读取成功 | “未充电” |
| 读取失败/样本过期 | “数据暂不可用” |

多口只显示总功率，是为了避免 320×240 上塞四组数字导致字号太小。

## 6. 端到端延迟

链路：

```
设备实际输出
  -> 云端属性（约 1～5 秒）
  -> 电脑 5 秒采样
  -> 电脑 5 秒重画 GIF
  -> 设备每秒取图
```

典型 1～6 秒，不承诺严格 1 秒。硬件监测模式和账户工作台模式用同一套 5 秒采样口径。

## 7. 常见误判

| 现象 | 不是这个原因 | 真正原因 |
|---|---|---|
| 插上手机屏幕还显示“未充电” | 功率读不到 | 画面链路太慢/没插稳/端口不对 |
| 功率一直是 0 | 解码公式错 | 手机已经充满/线不支持 PD/端口没输出 |
| 功率跳变大 | 解码错 | 手机充电策略在调压调流，正常 |
| 四个口只有一个有数 | 其它口坏了 | 其它口没插设备，正常 |

验证方法：插上手机，等 10 秒，读 `run/current.json` 里的 `power.ports`，
看四个端口的 `volts/amps/watts` 是否有一个非零。
如果有，但屏幕没显示，问题在传图链路，不在功率。
