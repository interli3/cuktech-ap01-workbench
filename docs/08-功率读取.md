# 08 充电功率读取

## 1. 先分清三种「功率」

这三个数经常被混为一谈，屏上显示错了多半是这里搞混：

| 名称 | 含义 | 例子 | 从哪来 |
|---|---|---|---|
| 接口标称上限 | 接口硬件规格，永远不变 | `C2 120W MAX`、`C1 140W MAX` | 原厂页固定文字 |
| 协商/分配档位 | 这一次握手谈成哪一档 | `PPS 55W`、`PPS 100W`、`PD 15W` | `piid=12` 握手字段 |
| 实际输出功率 | 设备此刻真正取走多少 | `7.8W`、`29.3W` | 电压 × 电流 |

**「档位」不是「实际输出」。** 手机标 100W 档位、实际只取 7.8W 是常态；
把实际 28W 写成「28W 档位」是错的，那一档根本不存在。

## 2. 数据在哪

充电端口信息在 MIoT service 4。只读这六个属性：

| siid | piid | 内容 |
|---:|---:|---|
| 4 | 1 | 功率分配模式 |
| 4 | 4 | C1 |
| 4 | 7 | C2 |
| 4 | 9 | C3 |
| 4 | 11 | USB-A |
| 4 | 12 | C1/C2 握手协议（高 16 位 C1，低 16 位 C2） |

一次打包请求全部取回，不要拆成多次：

```json
{
  "method": "get_properties",
  "params": [
    {"did": "你的DID", "siid": 4, "piid": 1},
    {"did": "你的DID", "siid": 4, "piid": 4},
    {"did": "你的DID", "siid": 4, "piid": 7},
    {"did": "你的DID", "siid": 4, "piid": 9},
    {"did": "你的DID", "siid": 4, "piid": 11},
    {"did": "你的DID", "siid": 4, "piid": 12}
  ]
}
```

不要一次查上百个属性，云端会返回空列表。

## 3. 端口值怎么解包

每个端口的值是一个 32 位整数：

```python
volts = ((value >> 24) & 255) / 10
amps  = ((value >> 16) & 255) / 10
watts = volts * amps
```

低 16 位是别的字段，不参与电压电流计算。

例子：`0xC30F1703`

```
最高字节 0xC3 = 195 -> 19.5 V
次高字节 0x0F = 15  -> 1.5 A
功率 = 19.5 × 1.5 = 29.25 W
```

与原厂功率页一致。

## 4. 模式（piid=1）

| 值 | 模式 |
|---:|---|
| 1 | AI智配 |
| 2 | 极速单充 |
| 3 | 均衡输出 |
| 4 | 自定义 |

只读取，不写。改模式要在米家 App 里改，本仓库不碰 `set_properties`。

## 5. 协议与档位（piid=12）

这是一个 32 位整数，**高 16 位是 C1，低 16 位是 C2**。
同时插 C1 手机和 C2 吹风机时返回 `0x08C20296`，两边各自独立。

每个半字再拆：

```python
code = (handshake >> shift) & 0xFFFF      # shift = 16 取 C1，0 取 C2
kind, tier = code >> 8, code & 255        # 高字节=协议类型，低字节=档位
protocol = {7: "PD", 8: "PPS"}.get(kind)
```

实测对照表（只收这几条，都是和原厂屏逐条核对过的）：

| 场景 | 半字 | 原厂/米家显示 | 本仓库解出 |
|---|---|---|---|
| C1 手机，多口同时使用 | `0x08C2` | PPS 45W | PPS 45W |
| C2 手机，分配后 | `0x0826` | PPS 55W | PPS 55W |
| C2 手机，单独使用 | `0x08E8` | PPS 100W | PPS 100W |
| C1 手机，低功率阶段 | `0x0796` | PD 15W | PD 15W |
| C2 吹风机 | `0x0296` | 只显示 `5V` | 档位 5V，协议未知 |
| 空闲 | `0x00960096` | 无输出 | 不绑协议 |

```python
PPS_GEARS = {0xE8: 100, 0x26: 55, 0xC2: 45}
PD_GEARS  = {0x96: 15}
```

### 为什么不写通用公式

低字节恰好符合「瓦数 × 10 取最低字节」，看起来能一眼反推。
**但没有这么实现**，两个原因：

1. 原厂固件能显示带小数的瓦数，单字节可能有多义；
2. 一档没对过的编码会被算成一个「看起来合理」的假档位，比显示「未知」更坏。

所以只查表。表里没有的一律显示「协议未知 / 档位未知」，不报错、不瞎猜。
UFCS、QC 以及其它 PD/PPS 瓦数目前都在「未知」里，原因是没有原厂对照。

### 只给正在输出的口绑定

握手字段会保留上一次的编码。空闲口也带着 `0x08E8` 时，
如果不判断「这一刻实际功率 > 0」，屏幕上会出现「没插东西却在跑 100W」。

## 6. 采样和过期

`tools/power_reader.py`：

- 独立后台线程，每 5 秒读一次六属性；
- 四个端口必须全部返回合法整数，才更新缓存；
- `type(value) is int` 排除布尔值（`False` 会被当成 0）；
- 读失败不写 0，旧样本自然过期；
- 样本超过 15 秒，`sample()` 返回 `None`，界面显示「数据暂不可用」；
- `piid=12` 单独失败时，四口功率照常显示，只是协议降级为「未知」。

为什么不做「失败就显示 0」：插着手机但云端读失败时，
0W 会让人以为没在充电，比「不可用」更误导。

## 7. 显示规则

| 情况 | 屏幕 |
|---|---|
| 一个端口 `watts > 0` | 接口 + 模式；大号实际 W；右列三行：档位 / 协议 / 电压电流 |
| 两个以上端口 `watts > 0` | 总 W；右侧前两个活动口各一行「接口 协议 档位」+「V A」 |
| 全部 0 且读取成功 | 「未充电」 |
| 读取失败 / 样本过期 | 「数据暂不可用」 |

多口时只列前两个口，是 320×240 放不下四组详情；
**总功率仍然是四口之和**，不遗漏。

`piid=12` 只覆盖 C1/C2。C3 和 USB-A 有实际 V/A/W，但协议和档位显示「未知」。

## 8. 端到端延迟

```
设备实际输出
  -> 云端属性（约 1～5 秒）
  -> 电脑 5 秒采样
  -> 电脑每秒重画、每 5 秒复制新样本
  -> 设备每秒取图
```

典型 1～6 秒，不承诺严格 1 秒。硬件监测模式和账户工作台模式共用同一套采样口径。

### 画面为什么必须每秒重绘

边框跑马灯是按相位逐帧画的，一秒只换一张图会「一跳一格」。
所以主循环固定每秒走一圈，充电数据另按 5 秒节奏复制。

### 账户请求不能占住主循环

`collect()` 要依次请求 Codex、WorkBuddy、DeepSeek 三个源，网络慢时会卡十几秒。
它跑在主循环里时，这段期间既不重绘也不复制充电样本 ——
表现就是「功率数字半天不动」，看起来像充电变慢了，其实是画面被账户请求堵住。

修法是把这个采集丢进 `ThreadPoolExecutor(max_workers=1)`：

```python
power_reader()                    # 先起充电线程，别排在账户请求后面
executor = ThreadPoolExecutor(max_workers=1)
data = refresh()
balance_future = None
balance_due = time.monotonic() + 60
power_due = time.monotonic() + 5

while True:
    time.sleep(1)
    now = time.monotonic()
    if balance_future and balance_future.done():
        updated = balance_future.result()
        for name in ('codex', 'workbuddy', 'deepseek'):
            data[name] = updated[name]        # 只回写账户字段
        data['checked_at'] = updated['checked_at']
        balance_future = None
    if now >= balance_due and balance_future is None:
        balance_future = executor.submit(collect)
        balance_due = now + 60
    if now >= power_due:
        refresh_power(data)
        power_due = now + 5
    else:
        publish(data)
```

🔴 **合并结果时只回写账户字段，不要整份 `data` 替换。**
整份覆盖会把主循环刚更新的充电样本换回后台线程启动时的旧值，
等于每 60 秒把功率显示回退一分钟。

## 9. 常见误判

| 现象 | 不是这个原因 | 真正原因 |
|---|---|---|
| 插上手机屏幕还显示「未充电」 | 功率读不到 | 画面链路太慢 / 没插稳 / 端口不对 |
| 功率一直是 0 | 解码公式错 | 手机已充满 / 线不支持 PD / 端口没输出 |
| 功率跳变大 | 解码错 | 手机充电策略在调压调流，正常 |
| 四个口只有一个有数 | 其它口坏了 | 其它口没插设备，正常 |
| 档位显示「未知」 | 程序坏了 | 该编码没有原厂对照，按设计不猜 |
| 新屏功率变化比旧屏慢 | 采样慢 | 账户请求堵住主循环（见 8 节） |

验证方法：插上设备等 10 秒，读 `run/current.json` 里的 `power`，
看 `mode`、各口 `volts/amps/watts`、以及有输出口的 `protocol/gear_watts`。
有数但屏上没有，问题在传图链路，不在功率读取。
