# 09 风险与未验证的范围

这一章不是免责声明凑字数，是复现前必须知道的边界。

## 1. 固件风险

| 风险 | 说明 | 降低办法 |
|---|---|---|
| 变砖 | 写入中断、断电、文件损坏都可能让设备起不来 | 用 UPS/笔记本电池，别在下载中休眠 |
| 失去保修 | 刷第三方固件通常不保 | 保留原厂 0031，必要时回刷 |
| 版本锁死 | 升到 0055 后目前没有降级方案 | 别在米家点升级 |
| 恢复失败 | 设备彻底离线时软件发不进命令 | 只能售后/拆机，本仓库不提供点位 |

## 2. 0055 是单向门

再强调一次：

- `0041 → 0031` 是降级，已成功；
- `0041 → 0055` 是升级，不是降级；
- 0055 的文件布局、签名闸门、写入器行为都没有验证；
- 本仓库没有 0055 的刷法，也不建议任何人拿它做实验。

如果你已经把设备升到 0055，保持原样，等上游或售后。
不要用 0031 的加载器、预反转固件去试。

## 3. 网络和端口

- 脚本需要在本机监听 **443** 给设备下载固件。443 被占用时会失败；
- 防火墙/杀毒软件可能拦截入站连接，导致设备下载到一半断掉；
- 设备 IP、电脑 IP 变了，`/live.bin` 会 403，固件 URL 也会失效；
- 建议在路由器上给电脑和每块屏都配静态 DHCP 绑定；
- 不要用 Clash/代理的虚拟网卡地址当 `bind`，脚本会按到设备的实际路由选地址。

## 4. 账号和隐私

- 小米云登录、Codex 登录、DeepSeek 密钥都属于个人凭据；
- 本仓库不包含任何账号、密码、令牌或明文密钥；
- DeepSeek 密钥用 DPAPI 加密，换 Windows 用户/重装系统后要重新配置；
- `run/current.json` 含真实余额，`run/*.jsonl` 含设备 DID 和局域网 IP，
  这些都在 `.gitignore` 里，不要手动提交；
- 公开截图前把余额、DID、IP 打码或换成示例数据。

## 5. 上游依赖

本仓库依赖上游 `cuktech-ap01-firmware-tools` 的：

- `features/official_firmware_source`（小米云 RPC）；
- `tools/ota_https_serve.py`（HTTPS 固件服务）；
- `env/mi-cloud.env`（登录凭据）。

上游改接口、改目录、改登录流程，本仓库的脚本可能跟着失效。
这不是“代码写错了”，是外部依赖变了。遇到问题先看上游 README/commit。

## 6. 显示服务

- Codex 客户端升级会新建哈希目录，服务会自动扫描，但接口字段可能变；
- WorkBuddy 本机桥接 `8791` 不是公开 API，版本升级可能改字段；
- DeepSeek 余额接口可能限流/改返回结构；
- 电脑关机、未登录、休眠时，屏幕没有新图；
- 服务用“登录时触发”，不是 Windows 服务，因为 DPAPI 绑定当前用户。

## 7. 没有验证的部分

- 没有逐一验证所有游戏；PresentMon 在不同反作弊/渲染 API 下可能有差异；
- 没有做整机重启后的两屏回归；
- 没有做长时间睡眠/唤醒、路由器重启测试；
- C3、USB-A、多口功率做过代码和渲染测试，没有逐口插手机完成真机验收；
- 没有验证 0055 上的任何写入；
- 没有验证不同硬件版本（本仓库只针对 `BL618-BL4`）。

## 8. 可选：多台设备时的隔离

两台一起跑时，最容易出的错不是技术，是手滑：

- 刷错 DID；
- 端口写重；
- 事务文件共用；
- 防火墙规则只写了一条；
- 一台在下载，另一台也开始刷。

记住五个“不”：

1. 不共用 DID；
2. 不共用端口；
3. 不共用事务文件；
4. 不同时写两台；
5. 不在设备下载时重启电脑。

## 9. 法律和条款

- 固件版权归酷态科，本仓库只做个人恢复/研究存档；
- 刷机可能违反厂商保修条款；
- 通过小米云 RPC 操作自己的设备，仍受小米账号条款约束；
- 不要用这套东西做商业刷机、批量改装或绕过付费；
- 如果你要分发修改后的固件，先确认当地法律和上游许可。

## 10. 一句话

**能接受“可能变砖、可能失去保修、可能白忙一场”，再动手。**
接受不了，就只读文档，别刷。
